# 🤖 Claude-AutoRefresh: 告别 5 小时滚动等待，让你的工作工时与 Claude 刷新完美对齐！

这个项目用于在 macOS 上按指定时间点自动在后台执行一次极简的 Claude Code 交互：

```bash
claude -p "Hi"
```

其用途是利用 macOS 的用户级 `LaunchAgent`，按你的日常作息**自动、提前开启/刷新 Claude Code 的 5 小时滚动使用窗口**，从而最大程度保留你在实际高强度工作时的额度，避免在开发中途被迫陷入漫长、枯燥的 5 小时冷却等待。

---

## 💡 为什么需要这个项目？（核心逻辑与作息匹配）

使用 Claude Code 的开发者都熟悉它独特的 **5 小时滚动额度刷新机制**（当敲下第一行 Claude 指令时，5 小时的滚动冷却窗口便正式开始倒计时）。
如果我们在开发渐入佳境时耗尽了限额，等待它重新恢复的时间（往往需要好几个小时）会极大地打断工作流。

**Claude-AutoRefresh 的核心目的，正是为了解决“用完额度后漫长的刷新等待时间”。**

它通过在**你正式开始工作之前的一段时间，提前在后台自动“空跑一枪”**（发送一个无感的 “Hi” 交互），从而**强行将 5 小时滚动窗口的起点（及下一次重置时间）锚定在更早的时段**。
这样一来，即使你在后续高强度开发中耗尽了额度，由于窗口早就提前开启了，**你所需面临的剩余等待冷却时间将被大幅度缩短（甚至缩短到零，刚好接上重置）**！

### 🕒 默认黄金刷新作息匹配 (`08:30, 14:00, 19:10`)：

项目默认预设了 **3 个触发时间点**，针对“上午、下午、夜间”三个工作大块，将“无法避开的冷却期”强行平移并对齐到日常的非工作时段：

*   **🌅 08:30 | 晨间抢跑**：在你 9:30 正式开工前，8:30 帮你提前激活窗口。上午高强度开发用尽额度后，重置点是 13:30，冷却时间完美重合你的「午餐 + 午休」时间。
*   **☀️ 14:00 | 午后抢跑**：在你 15:00 开始下午大块工作前，14:00 提前激活。下午用尽后重置点是 19:00，冷却期完美重合你的「傍晚下班 + 通勤与晚饭」时间。
*   **🌌 19:10 | 夜间抢跑**：在你 20:30 左右开启夜间学习前，19:10 提前激活。深夜用完后，重置点是 24:10，冷却期完美落在你的「洗漱 + 睡眠」时段。

> [!TIP]
> **💡 黄金法则（支持弹性自定）**：
> 默认时间仅为模板。你完全可以编辑 `config.env` 中的 `SCHEDULE_TIMES` 来完全对齐你自己的工作节奏。
> 建议将触发时间设定为你**预计正式开始工作前的 1 ~ 2 个小时**（例如：10:00 开工，设在 08:00 触发，这样用尽后最快只需等 1 个小时即可完全重置！）。

## 🚀 快速开始

只需极简的 3 步，即可快速将项目运行起来：

### 1. 克隆项目到本地
首先打开终端，克隆本项目并进入目录：
```bash
git clone https://github.com/Neptuneeeeeeee/Claude-AutoRefresh.git
cd Claude-AutoRefresh
```

### 2. 一键运行与安装
在项目根目录运行安装脚本，脚本将为您自动复制默认配置并注册 macOS 系统服务：
```bash
./manage.sh install
```

### 3. 查看后台运行日志
安装完成后，您可以随时运行以下命令查看后台自动运行与刷新的日志：
```bash
./manage.sh logs
```

> [!IMPORTANT]
> **⚡️ 0 内存常驻 & 关机开机自启，一次运行，高枕无忧！**
> * **不占用任何常驻内存 (0 MB RAM / 0% CPU)**：本工具完美契合 macOS 原生 `launchd` 机制。它**不需要**像传统的 Python、Node.js 项目那样在后台保持常驻运行、挂起 sleep。它只在您设定的刷新点（如 08:30）被系统唤醒，执行极简的刷新（仅需约 5 秒），然后**立即完全退出进程**，绝不浪费哪怕 1KB 的系统内存。
> * **一次运行，永久全自动**：运行 `./manage.sh install` 之后，后台服务会自动接管。哪怕电脑关机、重启，该服务也会在系统启动后自动按时点工作，无需任何额外手动操作。
> * **自定义触发时间**：如果想修改时间，随时可以编辑自动生成的 `config.env` 中的 `SCHEDULE_TIMES`，然后再次运行 `./manage.sh install` 重新载入即可。

## 🛠️ 常用管理命令

在终端通过运行 `./manage.sh` 加子命令即可快速进行维护和测试：

```bash
./manage.sh test-now      # 立即在后台触发一次 Claude 刷新测试（跳过随机延迟）
./manage.sh status        # 检查当前后台定时服务运行状态
./manage.sh logs          # 查看后台运行日志（最近 50 行）
./manage.sh errlogs       # 查看后台错误日志
./manage.sh uninstall     # 停止服务，并干净地卸载与移除所有本地运行文件
```

## ⚙️ 核心配置项详解 (`config.env`)

*   `SCHEDULE_TIMES`: 触发时间点（格式 `HH:MM`，多个用英文逗号分隔）。
*   `MAX_RANDOM_DELAY_SECS`: 默认 `300`。最大随机延迟秒数，避免请求过于精确，设为 `0` 则到点立即触发。
*   `ENABLE_NOTIFICATIONS`: 默认 `true`。是否在开始刷新、成功或失败时向 macOS 通知中心发送系统弹窗提醒。
*   `REFRESH_MESSAGE`: 默认 `"Hi"`。发送给 Claude Code 的最短交互提示词。
*   `TARGET_WORKSPACE`: 默认 `"$HOME/.claude-autorefresh"`。Claude 执行时的临时工作目录。

## 🛡️ 安全与健壮性设计

*   **安全配置解析**：不采用 `source config.env` 加载，使用文本白名单逐行解析，完全杜绝因配置文件篡改而导致的恶意 shell 代码注入漏洞。
*   **权限沙箱隔离**：同步的运行副本及目录均设为严格的 `700`/`600` 权限，防止本机其他越权用户读取。
*   **并发排他锁**：配置了运行目录排他锁，防止极端情况下重复触发导致多个 Claude 进程冲突。
*   **环境鲁棒性**：在别人的电脑上哪怕未安装 `terminal-notifier`，通知功能也会自适应降级至 macOS 原生 AppleScript 通知，确保 100% 能够发出系统弹窗。
